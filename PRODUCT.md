# Product

## Register

product

## Users

Software teams and coding agents responding to a new vulnerability. During the demo, judges must understand the evidence lifecycle in seconds. In normal use, the primary reader is a coding agent acting on a structured GitHub Issue, with a developer reviewing the same evidence.

## Product Purpose

Aftershock matches a current advisory to an exact repository revision, runs a restricted differential check, publishes agent-ready GitHub work, retests the remediation, and withdraws reassurance when the code or check changes. Success means the interface makes the difference between a version match, an observed effect, a retested fix, and stale evidence unmistakable.

## Brand Personality

Forensic, urgent, credible. The product should feel like a trusted incident instrument during a live response: dense enough for experts, clear enough for a three-minute judging video, and restrained about every claim.

## Anti-references

Avoid generic SOC dashboards full of decorative charts, terminal cosplay, neon hacker imagery, glossy marketing cards, and interfaces that use color without displaying the underlying evidence. Do not resemble Hacker Bob.

## Design Principles

1. Put the current evidence state and exact repository SHA first.
2. Show the control matrix that earned the state.
3. Bind every claim to a source, capsule revision, receipt, and public GitHub artifact.
4. Use state transitions to explain the product, especially remediation becoming stale after code changes.
5. Keep fixture replay and recorded evidence visibly labeled.

## Accessibility & Inclusion

Target WCAG 2.2 AA. Never use color as the only state signal. Preserve keyboard focus, readable contrast, responsive layout, and a reduced-motion path for every transition.
